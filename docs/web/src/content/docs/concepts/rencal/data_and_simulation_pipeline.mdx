# RenCal Data and Simulation Pipeline

This page gives a high-level map of the RenCal workflow from external data sources to simulation outputs.

## Pipeline at a glance

```text
External APIs
  -> DataDownloader (writes local artifacts)
  -> DataLoader (reads and normalizes artifacts)
  -> Dataset Models (validated data contracts)
  -> Calibration (fit technology-specific relationships)
  -> Simulation (sample historical weather-conditioned behavior)
  -> Forecast-ready streams and metrics
```

## Stage 1: Data acquisition

RenCal downloads source data from CDS, LCCC, and Elexon, then stores normalized artifacts under the project data directory.

- ERA5 weather files (`.nc`)
- plant + BMU mappings (`.csv`)
- generation time series (`.parquet`)

See [Data Downloader Architecture](/concepts/rencal/core/data_downloader_architecture/).

## Stage 2: Data loading and normalization

`LocalDataLoader` reads local artifacts and applies ingestion-time normalization (for example plant ID alignment and ERA5 variable selection).

See [Data Loader Architecture](/concepts/rencal/core/data_loader_architecture/).

## Stage 3: Dataset validation boundary

Loader methods return typed model objects:

- `PlantDatasetModel`
- `GenerationDatasetModel`
- `ERA5DatasetModel`

These models enforce schema and type checks (via Pydantic + model validators), creating a fail-fast boundary before calibration and simulation.

See [Dataset Models](/concepts/rencal/models/dataset_models/).

## Stage 4: Calibration

Calibration modules fit plant/technology relationships between weather drivers and generation behavior (for wind, logistic + Weibull components).

Start here:

- [Wind Power Curve Calibration](/concepts/rencal/calibration/wind_power_curve_calibration/)
- [Logistic Power Curve](/concepts/rencal/calibration/logistic_power_curve/)
- [Weibull Wind-Speed Distribution](/concepts/rencal/calibration/weibull_wind_speed_distribution/)

## Stage 5: Simulation and sampling

Simulation uses calibrated/historical artifacts to sample future periods while preserving seasonal structure through bucketing.

In code terms, this stage combines:

- `IntermittentBucketer` (`draw_period` block selection by seasonal bucket),
- `WeatherData` (historical slicing + optional average overrides),
- `BucketedData` utilities (histograms and optimized distribution transforms),
- `VersionedColumnsNDArray` output (canonical streams plus transformed versions).

Start with [Weather Data Sampling](/concepts/rencal/simulation/weather_data_sampling/).
For bucket design details, see [Bucketing Strategy](/concepts/rencal/simulation/bucketing_strategy/).
