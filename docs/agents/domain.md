# Domain Docs

This is a single-context repository. Engineering skills should use the project documentation under `docs/` when exploring the codebase.

## Before exploring

- Read `docs/CONTEXT.md` when it exists.
- Read relevant project documentation under `docs/`.

Domain context and terminology should be recorded in `docs/CONTEXT.md` when established. Architecture Decision Records are intentionally deferred; do not create or expect a `docs/adr/` directory unless the project adopts ADRs later.

If the context file does not exist, proceed without flagging its absence. Create it lazily when domain terms need to be established.
