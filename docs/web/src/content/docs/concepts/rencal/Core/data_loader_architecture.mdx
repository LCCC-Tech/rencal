# Data Loader Architecture

The [`rencal.core.data_loader` module](/reference/rencal/core/rencalcoredata_loader/) defines how RenCal ingests plant, generation, and weather data.
Its main design goal is to separate:

- **what** the rest of the system needs ([`DataLoader`](/reference/rencal/core/rencalcoredata_loader/#dataloader) interface), from
- **how** data is fetched and validated ([`LocalDataLoader`](/reference/rencal/core/rencalcoredata_loader/#localdataloader) implementation).

This keeps calibration and simulation logic storage-agnostic while preserving strict validation.

## Why this abstraction exists

RenCal consumes multiple data shapes and formats:

- plant metadata (tabular),
- generation time series (tabular),
- ERA5 weather cubes (xarray/netCDF).

Without a loader abstraction, these file-format details would leak into downstream logic.
With [`DataLoader`](/reference/rencal/core/rencalcoredata_loader/#dataloader), consumers ask for typed datasets and do not care whether the source is local files today or another backend tomorrow.

## Abstract contract: [`DataLoader`](/reference/rencal/core/rencalcoredata_loader/#dataloader)

[`DataLoader`](/reference/rencal/core/rencalcoredata_loader/#dataloader) is an abstract base class with three required methods:

- [`load_plant_data()`](/reference/rencal/core/rencalcoredata_loader/#dataloaderload_plant_data) -> [`PlantDatasetModel`](/reference/rencal/models/rencalmodelsplant_model/#plantdatasetmodel)
- [`load_generation_data()`](/reference/rencal/core/rencalcoredata_loader/#dataloaderload_generation_data) -> [`GenerationDatasetModel`](/reference/rencal/models/rencalmodelsgeneration_model/#generationdatasetmodel)
- [`load_era5_data()`](/reference/rencal/core/rencalcoredata_loader/#dataloaderload_era5_data) -> [`ERA5DatasetModel`](/reference/rencal/models/rencalmodelsera5_model/#era5datasetmodel)

This defines RenCal's ingestion contract for all implementations.

## Concrete implementation: [`LocalDataLoader`](/reference/rencal/core/rencalcoredata_loader/#localdataloader)

[`LocalDataLoader`](/reference/rencal/core/rencalcoredata_loader/#localdataloader) implements the contract against local files under `DOWNLOAD_DATA_DIR`.

### Data sources and behavior

- **Plant data:** reads CSV, standardises ID column, returns [`PlantDatasetModel`](/reference/rencal/models/rencalmodelsplant_model/#plantdatasetmodel).
- **Generation data:** reads Parquet, standardises ID column, returns [`GenerationDatasetModel`](/reference/rencal/models/rencalmodelsgeneration_model/#generationdatasetmodel).
- **ERA5 data:** discovers `.nc` files, normalises time dimension to `time`, casts weather variables to `float32`, concatenates/sorts, filters to standard variables, returns [`ERA5DatasetModel`](/reference/rencal/models/rencalmodelsera5_model/#era5datasetmodel).

### Reliability helpers

The loader also includes calibrated weather helpers and manifest verification utilities:

- [`check_historical_weather()`](/reference/rencal/core/rencalcoredata_loader/#localdataloadercheck_historical_weather)
- [`get_historical_weather()`](/reference/rencal/core/rencalcoredata_loader/#localdataloaderget_historical_weather)
- [`get_prefix_histograms()`](/reference/rencal/core/rencalcoredata_loader/#localdataloaderget_prefix_histograms)
- [`verify_npy_against_manifest()`](/reference/rencal/core/rencalcoredata_loader/#localdataloaderverify_npy_against_manifest)

[`verify_npy_against_manifest()`](/reference/rencal/core/rencalcoredata_loader/#localdataloaderverify_npy_against_manifest) performs integrity checks (SHA-256 hash, file size, and schema sanity checks), helping ensure simulation/calibration runs consume expected artifacts.

## Data loaders return dataset models

The loader layer returns validated model objects from [`rencal.models.base`](/reference/rencal/models/rencalmodelsbase/) and its concrete model modules rather than raw files.

| Loader method | Return type | Backing data |
| :-- | :-- | :-- |
| [`load_plant_data()`](/reference/rencal/core/rencalcoredata_loader/#dataloaderload_plant_data) | [`PlantDatasetModel`](/reference/rencal/models/rencalmodelsplant_model/#plantdatasetmodel) | `pandas.DataFrame` |
| [`load_generation_data()`](/reference/rencal/core/rencalcoredata_loader/#dataloaderload_generation_data) | [`GenerationDatasetModel`](/reference/rencal/models/rencalmodelsgeneration_model/#generationdatasetmodel) | `pandas.DataFrame` |
| [`load_era5_data()`](/reference/rencal/core/rencalcoredata_loader/#dataloaderload_era5_data) | [`ERA5DatasetModel`](/reference/rencal/models/rencalmodelsera5_model/#era5datasetmodel) | `xarray.Dataset` |

This creates a stable handoff boundary:

```text
Storage/files -> DataLoader implementation -> DatasetModel objects -> Calibration/Simulation
```

## Extending to new backends

To support new sources (for example S3 or API-backed ingestion), implement a new [`DataLoader`](/reference/rencal/core/rencalcoredata_loader/#dataloader) subclass that returns the same three model types.

```python
class S3DataLoader(DataLoader):
    def load_plant_data(self) -> PlantDatasetModel: ...
    def load_generation_data(self) -> GenerationDatasetModel: ...
    def load_era5_data(self) -> ERA5DatasetModel: ...
```

As long as the contract is preserved, downstream code remains unchanged.
